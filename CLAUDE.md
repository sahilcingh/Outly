# Working style

Default to the `ponytail` philosophy for every coding task in this repo (writing, adding, refactoring, fixing, or reviewing code, and choosing libraries/dependencies): the simplest, shortest, most minimal solution that actually works.

- Question whether the task needs new code at all before adding any.
- Reach for the standard library / existing project utilities before a new dependency.
- No speculative abstractions, config flags, or "future-proofing" for requirements that don't exist yet.
- Prefer one obvious line over a clever or generalized one.
- If a skill named `ponytail` is available, invoke it for non-trivial changes instead of reasoning about minimalism from scratch.
